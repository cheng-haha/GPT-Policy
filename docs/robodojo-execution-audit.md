# RoboDojo 执行限制审计

范围：GPT_Policy 的单环境 RoboDojo 路径。2026-09-23。

## 已修改

`model.py` 默认 TCP z 范围由 `[0.04, 0.45]` 改成 `[null, 0.45]`；
不再默认限制最低高度。显式设置 `robodojo_reachability_bounds` 仍可覆盖默认值。
有效边界会进入模型提示与观测。工作空间拒绝改标为 `workspace_limit`，
附带 `ik_checked=false`，避免被误认为机械臂 IK 已证明不可达。

## 可能中断执行的限制

| 项目 | 实际行为 | 建议 |
|---|---|---|
| 连续跟踪失败 | `model.py` 中任一臂位置误差 >3 cm、角度误差 >0.20 rad，或模拟器标记 tracking_failed，连续两次观测后设 execution_blocked；deploy 强制失败结束 | 优先改为先报告误差、允许撤回或重新规划；仅对明确异常或持续不可恢复状态结束 |
| 双层跟踪阈值 | 模拟器 `eval_env.py` 另有写死的 3 cm 阈值；策略将这个状态与自身阈值取 OR。只调策略阈值不能关闭该分支。反馈 within_tolerance 则使用 1.5 cm | 统一配置来源，区分“尚未到位”和“必须停机” |
| 固定工作空间 | base x∈[-0.05,0.65]、y∈[-0.55,0.55]、z≤0.45 m；越界动作被替换为保持，未尝试 IK | 用机器人/场景配置覆盖，避免把经验矩形当真实可达域 |
| 单步位移上限 | 任一 TCP 相邻请求距离 >0.30 m 拒绝整个动作；chunk 每个点也检查 | 可自动分段，或由模型分段；无需直接结束回合 |
| give_up | 模型输出一次 give_up，deploy 即按失败结束，没有恢复次数门槛 | 改善失败原因和恢复信息；若需恢复阶段，应明确设计，避免无限重试 |
| 工具/模型请求异常 | 未支持工具、无效输出、缺失图像/状态等通常抛异常；overloaded 最多调用 5 次，其余模型错误没有同样的恢复循环 | 对可恢复格式/瞬时服务错误做有限重试；保留真实错误原因 |
| 顺序脚本遇失败退出 | RoboDojo sweep 只要有评估失败就 exit 1，selected 脚本立即退出。因此动作执行正常但任务不成功也会阻止后面任务 | 将单任务评估失败与启动故障分开记录，批次继续，最后统一非零退出 |

## 会降低效率，但不直接终止的项目

- settle_control 最多等待 2 秒**仿真时间**，关节误差 ≤0.001 rad、速度 ≤0.01 rad/s，连续三帧才算稳定；超时写 settled=false，本身不会直接给回合判失败。
- locate_point 要求视差角 ≥5°、条件数 ≤500、射线残差 ≤0.01 m、交点在相机前方。未通过时不提供有效三维点，模型可以换视角；不能简单当成任务不可完成。
- check_path 的工具说明声称检查 IK/路径，但 RoboDojo 实现只返回 path_check_available=false 和保持动作。模型反复调用可能浪费步数，应隐藏该工具或对该后端改正说明。
- 拒绝动作、定位、check_path 等产生的保持动作仍经过 take_action，会占用 RoboDojo 的步数。
- done 未得到 RoboDojo 成功确认时会退回模型继续执行；反复 done 请求没有单独的恢复上限，而且该分支可能没有新环境动作，存在长时间循环风险。
- ICL 选择器异常被静默吞掉并回退均匀抽帧；它不直接终止任务，但可能缺少 subtask 注释。

## 不能误认为额外策略限制的设置

- RoboDojo 任务步数上限：fold_clothes 500、arrange_largest_number 1050、pack_objects_into_box 1300。这是评估定义的一部分。
- 本路径没有使用配置中的 runtime.max_decisions=100 作为停止条件。
- WebSocket request_timeout_s=null；120 秒是等待提醒，不是超时退出。Codex 也未设固定请求超时。
- batch=false 是当前适配器的数据契约，不是任务难度限制；启用多环境会触发 NotImplementedError。
- 关节速度 1 rad/s、加速度 4 rad/s²用于生成动作时长，通常让执行更慢而非直接拒绝动作。

除 TCP 最低高度及对应说明外，本次审计未自动删除其余限制。
